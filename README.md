## ✨ 核心特性

### 网页管理
- **零依赖 Web UI**：内置 NanoHTTPD + 单页 `index.html`，浏览器打开即用，不需要装客户端。
- **文件浏览 / 下载 / 上传**：目录逐级浏览，文件点击下载，上传自动保存到当前目录。
- **响应式极简界面**：手机、平板、电脑浏览器均可用。

### 本地管理
- **App 内文件管理器**：启动服务、查看 IP、浏览目录、打开文件、重命名、删除、新建文件夹。
- **服务状态实时显示**：运行中 / 已停止，一键启停。
- **文件操作与 Web 端互通**：本地删改的文件，Web 端刷新后立即同步。

### 低版本兼容与常驻
- **极低兼容**：最低支持 Android 2.2 (API 8)，现代手机也可完美运行。
- **无 AndroidX 依赖**：纯 Framework API，不引入 Support Library。
- **开机自启**：静态 `BOOT_COMPLETED` 广播，重启后自动拉起服务。
- **前台服务保活**：常驻通知 + `START_STICKY`，降低被系统回收概率。

### 自动化
- **GitHub Actions 自动构建**：推送到 `main` / `master` 即触发，产物在 Actions 页面下载。
- **一键生成脚本**：Python 脚本自动生成完整项目、Gradle Wrapper、git 初始化，可选自动创建 GitHub 仓库并推送。

## 快速上手

### 1. 局域网访问
安装 APK，**先手动打开一次 App**（Android 3.1+ 要求应用至少启动过一次，之后开机自启才会生效）。
记下 App 首页显示的地址，在局域网浏览器打开：

```text
http://手机IP:8080
```

### 2. 文件管理
- **浏览**：点击目录进入，点击“上级目录”返回。
- **下载**：文件右侧点击“下载”。
- **上传**：在任意目录选择文件上传，自动保存到当前目录。
- **本地管理**：App 内点击或长按文件，可打开 / 重命名 / 删除 / 查看属性；菜单键可新建文件夹。

### 3. 开机自启
首次手动打开 App 后，重启设备，服务会自动运行。
通知栏会常驻“Android NAS 运行中”。

## 🛠 自行编译

本项目使用 **AGP 4.2.2 + Gradle 6.7.1 + JDK 8** 构建，专门为了支持 `minSdkVersion 8` 而保留的古早工具链。

```bash
# 本地构建
./gradlew assembleDebug
```

APK 位置：

```text
app/build/outputs/apk/debug/app-debug.apk
```

代码推送到主分支后，GitHub Actions 会自动完成编译，产物在 Actions 页面的 `android-nas-debug` artifact 中。

## 架构局限性与风险提示（重要）

1. **首次启动限制**：Android 3.1+ 要求应用至少被手动启动过一次，否则收不到 `BOOT_COMPLETED`。安装后必须先打开一次 App。
2. **明文 HTTP**：局域网传输使用明文 HTTP，无 TLS 加密，仅建议在可信内网使用，不要暴露到公网。
3. **存储权限**：`targetSdkVersion 22` 依赖系统兼容模式授予存储权限。如果用户在系统设置中手动关闭存储权限，文件操作会失败。
4. **低内存设备保活**：前台服务能降低被回收概率，但在极低内存设备上仍可能被杀。重新打开 App 或重启设备后服务会恢复。
5. **古早工具链的技术债**：为强制支持 API 8，项目锁死了 AGP 4.2.2 / Gradle 6.7.1 / JDK 8，升级工具链需要重新评估低版本兼容性。

**总结**：Android NAS 适合极客折腾、内网文件共享、旧手机再利用。日常跨平台文件传输，建议使用更现代的方案。
