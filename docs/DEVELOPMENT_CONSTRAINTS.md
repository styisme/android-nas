# 开发环境约束说明

本项目由一名开发者**全程在 Android 手机 / 智能手表上完成**。没有本地 IDE，没有 Android SDK，没有 Gradle 守护进程。所有编译、打包、发布均在 GitHub Actions 云端完成。

这份文件的目的，是**诚实披露这种极端约束下的开发现实**，并明确我们如何承担与"有本地工具的开发者"同等的产品责任。

---

## 一、我们无法做到的事

以下标准开源流程，本项目**物理上无法执行**：

| 标准流程 | 为什么做不到 |
|---|---|
| 本地 `./gradlew assembleRelease` | 手机/手表上没有 JDK、没有 Android SDK、没有 Gradle |
| 逐行 diff 审阅敏感代码 | 手表屏幕放不下 diff 视图，也没有本地 diff 工具 |
| 运行 lint / spotbugs / 单元测试 | 本地无工具链，无法执行 |
| 标准 PR 流程（fork → branch → PR → review） | 走的是直推 master（Mgit），CI 是唯一门禁 |
| 本地静态分析 | 同上 |

**我们不假装这些做过。** 任何声称"已通过逐行审阅"的表述，如果来自本项目，都是不准确的。

---

## 二、我们如何承担人类责任

标准流程缺失，**责任并不缺失**。以下是我们实际执行的责任机制：

### 1. AI 参与度透明披露

见 [`AI_DISCLOSURE.md`](AI_DISCLOSURE.md)。本项目约 **99% 的代码由 AI 生成**，人类开发者负责产品决策、真机测试、错误反馈与发布裁决。这是事实，不美化。

### 2. 高危功能默认关闭 + 单独警告

见 [`SECURITY.md`](../SECURITY.md)。以下功能**默认全部关闭**，且在使用前有独立警告章节：

- Root 全盘模式
- Web Shell 终端
- H264 远程控制 / 无障碍触控
- IP 白名单（锁死风险）
- 终极自毁 (Panic Wipe)

### 3. CI 编译门禁

**编译不通过，不发版。** 这是本项目唯一的自动化门禁。所有版本必须经过 GitHub Actions 矩阵编译通过，才会有 Release 产物。

### 4. 真机 / 真实环境验证

每一次发布前，代码在**真实的旧手机、电视盒子、智能手表**上测试。这不是形式化的"我跑过了"，而是"我手机上现在装的这个 APK，就是我发出去的这个版本"。

### 5. 变更可追溯

`CHANGELOG.md` + 自动打 tag + 平铺发布。每一个 release 都能追溯到具体的 CHANGELOG 条目和对应的 commit。

## 三、敏感模块特别清单

以下模块**每次改动都在真机上验证过**（不只是 CI 编译通过）：

- `AuthManager.java` — ThreadLocal 并发身份隔离
- `NasHttpServer.safeFile()` — 路径沙箱映射
- `WebDavServer.java` / `FtpServer.java` — 纯 Socket 协议解析
- `RemoteDesktopManager.java` — WebSocket Token 鉴权
- `AdvancedKeepAliveManager.java` — Root 命令执行
- `DatabaseManager.hash()` — 密码加盐哈希
- `.github/workflows/build-all.yml` — Keystore 注入与签名

---

## 四、我们承认这不完美

形式化的 PR 流程、逐行代码审阅、本地静态分析，这些在本项目里**全部缺位**。我们用「**披露 + 门禁 + 真机 + 默认关**」四件事承担了**实质责任**，而不是**形式责任**。

这是约束下的选择，不是对标准的否定。

如果你在别的项目上看到这套机制，并觉得"为什么不照做 PR 流程"——请先问自己：**你能在手表上敲出 `git diff` 吗？**

---

## 五、给其他移动端开发者的建议

如果你也在极限约束下开发，这套最小责任清单供你参考：

1. **诚实披露 AI 参与度**（不要美化比例）
2. **高危功能默认关闭**（代码层面，不是文档层面）
3. **CI 编译门禁不可绕过**（编译不过就不发版）
4. **真机测试，不是"模拟器跑过了"**
5. **敏感模块清单公开**（让外部能核对你测过什么）

**五件事做到了，你就已经承担了人类责任。** 形式上像不像别人，不重要。
